# Dive Computer Simulator

An interactive, browser-based trainer that shows how real dive computers behave – and how differently they handle the same dive.
Built because the simulators offered with agency eLearning (a generic drag-the-diver app and pre-rendered Suunto "virtual dives") are
passive, generic and gated.

**Training only. Not for planning real dives.**

## What it does

- **Simulate** – drive a diver (target depth, descent/ascent speed, time acceleration up to 120×) and watch a faithful recreation of a real
  computer react: no-stop countdown, ascent-rate bars, safety-stop timers, deco stops and ceilings, alarms, violations, lock-outs, surface
  interval and no-fly time. Press its real buttons for plan mode, alternate screens, menus.
- **Six computers**: Suunto Zoop Novo, Shearwater Peregrine, Oceanic Veo 4.0 (the Aqua Lung i300C family, with the DSAT/Z+ "Dual Algorithm"),
  Mares Puck Pro+, Cressi Leonardo, and a generic PADI-style trainer.
- **Compare** – the same dive on every computer side by side, a live table of what each one shows, and a chart of their first-dive no-stop limits.
- **Lessons** – eight guided exercises with live checks and debriefs, mapped to the Open Water learning objectives (reading the display, turning the
  dive at the first limit, ascent-rate alarms, emergency decompression, missed stops and lock-outs, repetitive dives and plan mode, nitrox, dual
  algorithms).
- **Under the hood** – tissue compartments, ceiling, time to surface, GF99/SurfGF, CNS, and an event log that explains every alarm in the
  manual's own words.
- **Reference** – every behaviour is traced to a manual page; the full research notes are served from `docs/research`.

## Run it

```bash
npm install
npm run dev        # web app on http://localhost:5173, API on :3001
```

Other scripts: `npm test` (engine and behaviour tests), `npm run build` + `npm start` (production build served by the Node/Express server),
`npm run typecheck`.

## Architecture

```
src/engine      decompression models (pure TypeScript, no React)
  buhlmann.ts     ZH-L16C + gradient factors, Schreiner/Haldane loading, NDL, ceiling, stop schedule, GF99/SurfGF, desaturation
  dsat.ts         DSAT (PADI RDP) 14-compartment model + a Workman-slope ascent planner
  oxygen.ts       NOAA CNS clock and OTU
  calibration.ts  per-compartment M-value scales fitted to each manufacturer's published table (generated by tools/fit-mscale.ts)
src/sim         brand-agnostic computer core (dive start/end, tissues, deco plan, safety-stop state machine, violations, alarms),
                world simulation (diver, clock, scripted profiles), React store
src/computers   one folder per computer: firmware.ts (brand rules + display model), Display.tsx (skin), index.ts (definition + references)
src/lessons     lesson definitions (steps with live checks)
src/components  UI: controls, profile chart, telemetry, compare, lessons, reference
server/         Express API: reference documents, saved dive log; serves dist/ in production
docs/research   research notes from the manufacturers' manuals and PADI material (quotations with page numbers)
tools/          calibration fitter, screenshot script
```

## Fidelity

- Shearwater runs Bühlmann ZH-L16C with gradient factors exactly as documented (presets 45/95, 40/85, 35/75).
- DSAT reproduces the PADI RDP and the Oceanic DSAT table within ~1 minute.
- Suunto RGBM, Pelagic Z+, Mares and Cressi RGBM are proprietary. They are approximated by ZH-L16C compartments whose surfacing limits were
  fitted to each manufacturer's published first-dive table (`tools/fit-mscale.ts`), so first-dive no-stop times match the manuals within about
  a minute; repetitive-dive and micro-bubble penalties are only partially reproduced. Mares prints no table and borrows the Cressi calibration;
  the Cressi table comes from an owner's display readings.
- Button logic covers the dive screens and the main surface screens; settings menus are simplified (use the Settings panel).
